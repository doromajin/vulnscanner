# セキュリティ診断レポート（サンプル）

| 項目 | 内容 |
|---|---|
| 対象 | Vulnerable Laravel App（講演用に作られた、意図的に脆弱な公開デモアプリ） |
| 版 | コミット `12b6444` |
| 診断日 | 2026-11-19 |
| 診断方法 | ソースコードの静的解析（VulnScanner）と、担当者によるコード確認 |
| 診断範囲 | リポジトリ内の PHP / Blade / JavaScript / 依存パッケージ定義 |
| 対象外 | 稼働中のサーバーへの接続・攻撃、動的な検証、インフラ設定 |

> **このレポートについて**: 営業用のサンプルです。対象は「意図的に脆弱」なデモアプリなので、件数は実運用のアプリの代表値ではありません。実案件では、同じ構成で、貴社のコードに対する結果をお渡しします。

## 1. 要約

診断の結果、**5 件**の指摘がありました。

| 重大度 | 件数 | 内容 |
|---|---|---|
| High | 3 | SQL インジェクション 1 件、パストラバーサル（ファイルパスの外部入力）2 件 |
| Medium | 1 | アップロードされたファイルの保存方法 |
| Low | 1 | 古い依存パッケージ（axios 0.19） |

**最優先の対応**は、次の 2 点です。

1. **一覧 API の `sort` パラメータ**が、そのまま SQL の並び順として実行されます。データベースの内容の読み出しや、改ざんにつながります。
2. **ファイル情報 API の `fileName` パラメータ**が、検証なしでファイル操作に渡されます。サーバー上の任意のパスへのアクセスや、アップロード済みファイルの悪用（PHP オブジェクトの注入）につながります。

## 2. 指摘一覧

| ID | 重大度 | 種別（CWE） | 場所 | 概要 |
|---|---|---|---|---|
| F-01 | High | SQL インジェクション（CWE-89） | `app/Http/Controllers/Api/EventController.php:18` | リクエストの `sort` が `orderByRaw()` に渡される |
| F-02 | High | パストラバーサル（CWE-22） | `app/Http/Controllers/Api/GetFileDetails.php:29-30` | リクエストの `fileName` が `Filesystem->size()` / `->lastModified()` に渡される |
| F-03 | Medium | 制限のないファイルアップロード（CWE-434） | `app/Http/Controllers/Api/FileUploader.php:16` | クライアントが指定したファイル名で保存される |
| F-04 | Low | 既知の脆弱性のある依存（CWE-1104） | `package.json` | `axios` 0.19 に既知の脆弱性が複数ある |

F-02 は、同じ原因で 2 行に出ています（件数は 5 件、原因は 4 件です）。

## 3. 指摘の詳細

### F-01 SQL インジェクション（High）

- **場所**: `EventController::index()`（18 行目）
- **内容**: リクエストの `sort` を、そのまま `orderByRaw()` に渡しています。`orderByRaw()` は、SQL の断片をそのまま実行する API です。
- **影響**: `routes/api.php` のルート定義に認証ミドルウェアがないため、未認証で呼べる可能性が高く（他の場所で制限されていないかは、動的な確認が必要です）、その場合、データベースの内容の読み取りや、変更につながります。
- **推奨対策**:
  - 並び替え可能な列を**許可リスト**で固定し、リストにない値は既定の列に置き換える。
  - 列名と向きを `orderBy($column, $direction)` に渡す（列名は許可リストの値のみ）。
  - 例: 許可する列を `['id', 'name', 'created_at']` に限定し、`in_array($sort, $allowed, true)` で確認する。

### F-02 パストラバーサル／オブジェクト注入（High）

- **場所**: `GetFileDetails::__invoke()`（29〜30 行目）
- **内容**: リクエストの `fileName` を、`Illuminate\Filesystem\Filesystem` の `size()` と `lastModified()` に渡しています。この API は、`Storage` のディスクと違って、ルートの制限がありません。入力のパスがそのまま使われます。
- **影響**:
  - アップロードディレクトリの外にあるファイルの情報の取得。
  - `phar://` 形式のパスを通じた、PHP のオブジェクトの復元（PHP 7 系の環境）。F-03 でアップロードされたファイルと組み合わさると、リモートコード実行につながる恐れがあります。
- **推奨対策**:
  - `basename()` でディレクトリ成分を取り除き、アップロードディレクトリを基準にした `realpath()` が、そのディレクトリの配下にあることを確認する。
  - `phar://` などのストリームラッパーを拒否する（`str_contains($name, '://')` を拒否）。
  - ファイルの参照は、ファイル名ではなく、データベースの ID で行う。
  - PHP を 8 系に上げる（`phar://` のメタデータが、自動では復元されなくなります）。

### F-03 制限のないファイルアップロード（Medium）

- **場所**: `FileUploader::__invoke()`（16 行目）
- **内容**: `putFileAs()` に、クライアントが指定したファイル名（`getClientOriginalName()`）を渡しています。拡張子も、クライアントの指定どおりになります。
- **影響**: スクリプトの拡張子で保存された場合、実行される恐れがあります。F-02 と組み合わさると、影響が大きくなります。
- **推奨対策**:
  - `store()` や `hashName()` で、サーバーが生成したファイル名を使う。
  - `mimes:` / `mimetypes:` の検証ルールで、許可する形式を限定する。
  - アップロード先を、Web から直接実行できない場所にする。

### F-04 既知の脆弱性のある依存（Low）

- **場所**: `package.json`
- **内容**: `axios` 0.19 に、複数の既知の脆弱性が報告されています。
- **推奨対策**: 現行の安定版に更新し、`npm audit` を CI に組み込む。

## 4. 診断の限界

- **静的解析のみ**です。実際に動かして確認する動的な検証は、行っていません。
- 指摘は、**コード上の危険な使い方**です。実際に悪用できるかは、環境（PHP のバージョン、設定、前段の保護）によって変わります。
- 見つからなかった領域があることは、**問題がない**ことを意味しません。ビジネスロジックの欠陥や、認可の設計ミスは、静的解析では見つけにくい領域です。
- 診断は、合法的な範囲内で、対象のコードに対してのみ行いました。稼働中のサーバーへの接続は、行っていません。

## 5. 次のステップ（実案件の場合）

1. 対象リポジトリと、診断範囲の確認（約 1 日）。
2. 静的解析と、コード確認の実施（対象の規模により 3〜5 日）。
3. 本レポートの形式での報告と、修正方針の説明会。
4. 修正後の再診断（任意）。
