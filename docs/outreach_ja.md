# 受託の見込み探し: 文面のたたき台

> 送信・投稿は、ご自身で行ってください。`【 】` の部分は、書き換えが要ります。実績として書けるのは、**実際にあったことだけ**です（下の「書いてよいこと・いけないこと」を参照）。

## 1. 書いてよいこと・いけないこと

| 書いてよい（事実） | 書かない |
|---|---|
| Laravel / Django の公開 OSS で、ツールの誤検出と取りこぼしを点検し、改善したこと | 「脆弱性を必ず見つけます」「ゼロにします」などの保証 |
| 手法は、静的解析と人によるコード確認だけで、稼働中のサーバーには触れないこと | 他社・他人のコードに、許可なくスキャンした結果 |
| 認可の設計ミスや、業務ロジックの欠陥は、静的解析では検出できず、コードを読む確認で補うこと | 公開 OSS の未修正の脆弱性の詳細（責任ある開示の前に、公にしない） |
| 責任ある開示で CVE を取得した経験（【番号と対象を、公開してよい範囲で】） | 顧客のコードや社名（NDA の範囲） |

## 2. 無料の簡易診断のご案内（知人の会社、副業可の開発者向け）

**件名**: 【Laravel / Django】ソースコードのセキュリティ診断（無料の簡易診断を 1 件ご提案）

【名前】様

突然のご連絡で、失礼します。【自己紹介を 1 文: 例）Laravel の受託開発をしている、【名前】です】。

個人で、Laravel / Django のソースコードを対象にした、セキュリティ診断を始めました。実績づくりのため、**無料の簡易診断を、先着 1〜2 件**で、お受けしています。

- **内容**: ソースコードの静的解析と、担当者による確認。指摘の一覧と、修正の方針を、日本語の報告書でお渡しします（形式の見本: 添付のサンプル報告書）。
- **お預かりするもの**: 対象のリポジトリ（コードの閲覧だけで足ります）。
- **守ること**: 秘密保持契約を結びます。コードは、私のローカルの PC だけで扱い、納品後に削除します。外部の AI サービスには、送りません。稼働中のサーバーには、接続しません。
- **条件**: 結果を、社名を伏せた事例として、公開してよい場合に限ります（難しい場合は、ご相談ください）。
- **できないこと**: 他人のデータが見えてしまうような、権限の設計の確認は、簡易診断の範囲外です（有料の標準診断で、主要な流れを確認します）。

ご興味があれば、【希望の日程】までに、ご返信ください。15 分ほどのオンラインで、対象と範囲を、すり合わせます。

## 3. クラウドソーシング用の自己紹介と提案文

### プロフィール（短縮版）

Laravel / Django のソースコードを対象にした、**静的解析と、人によるコード確認**のセキュリティ診断をしています。公開 OSS で、診断ツールの精度を点検し、改善してから、案件に臨みます。稼働中のサーバーへの接続や、攻撃は、しません。報告書は日本語で、修正の方針まで書きます。

### 提案文（案件への応募）

はじめまして、【名前】です。【案件名】の募集を拝見しました。

**できること**: 対象リポジトリの静的解析と、指摘の仕分け（担当者がコードを読んで、実際に危険なものだけを報告）、日本語の報告書（重大度、場所、影響、修正方針）。

**進め方**:
1. 対象と範囲の確認（版、除外するもの、秘密保持）
2. 静的解析と、コード確認
3. 報告書の納品（質問は、メール 2 往復まで）

**お伝えしておくこと**: 静的解析だけでは、認可の設計ミスや、業務ロジックの欠陥は、検出できません。必要な場合は、主要な流れを、コードで確認するメニューも、ご用意しています。

【納期の目安と、お見積りの考え方（リポジトリの規模で決まる）】

## 4. 実績の発信（記事・SNS）の案

自分の発信は、顧客の情報を含まないので、すぐ始められます。

| 題材 | 中身 | 注意 |
|---|---|---|
| 「Laravel のセキュリティ診断で、誤検出が起きる 5 つのパターン」 | 今回の点検で見つけた、同名の別物の取り違え、ファイル全体の粗い判定などを、API 名とコード片で解説 | 攻撃の手順や、ペイロードは書かない |
| 「静的解析で検出できないもの」 | 認可の設計ミス、業務ロジックの欠陥。サンプル報告書の診断範囲との対応 | — |
| 「依存パッケージ診断の落とし穴」 | 外部データベースへの照会が失敗したとき、無言で『問題なし』になる実装の罠と、その直し方 | 自作ツールの話に限る |

## 5. 候補の探し方（10 件挙げる）

条件（どれも、公開情報だけで確認できる範囲）:

- Laravel / Django で開発している、受託開発会社、EC、SaaS（小〜中規模）。
- 技術ブログや、求人で、使っている技術が分かる。
- セキュリティ担当の専任者が、いなさそうな規模（診断を外注する理由がある）。

探す場所: 勉強会や、コミュニティで知り合った人、自分の過去の取引先、クラウドソーシングの案件一覧。

> 候補の一覧は、**個人名や連絡先を、このリポジトリに保存しない**でください（個人情報になります）。手元のメモか、別の管理表で。

## 6. 契約前の確認（再掲）

1. 勤務先の就業規則（副業の可否、届出の要否）。**これが最優先**です。
2. NDA のひな形（弁護士や、公的な相談窓口で、確認するのが安全です）。
3. 診断範囲の書面（対象の版、除外、対象外として明記する項目: 認可の設計、業務ロジック）。
4. 契約の形は、準委任。「脆弱性ゼロ」の保証は、しません。
5. 開業届と、請求書の様式（売上が出てから）。
